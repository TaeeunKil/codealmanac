# Slice 190: Agent memory reconnection interface

> [!WARNING]
> **Incomplete design draft. Do not implement from this document.**
>
> The MCP-first architecture below predates the decision to evaluate selective
> absorption of NOOA's memory subsystem into AWM. The product boundary,
> integration model, and implementation stages still require redesign and
> explicit acceptance.

**Status:** incomplete draft, pending architectural revision

**Date:** 2026-08-11

**Audience:** implementation and review agents

**Scope:** Agent Work Memory active-memory service, stdio MCP adapter, review
surface, and NOOA integration example

## 1. Executive decision

Agent Work Memory (AWM) will add a provider-neutral, agent-facing memory
interface that lets an active agent:

1. load a small typed view of the current workspace state;
2. recall bounded durable knowledge and, only when explicitly authorized,
   retained session evidence;
3. dereference every returned item to its AWM source; and
4. propose new memory candidates without directly changing confirmed memory or
   the Markdown Vault.

The primary transport is a local **stdio MCP server**. AWM core will not depend
on NOOA. NOOA, Codex, Claude, and any other MCP host consume the same typed AWM
contract. A thin NOOA example proves the integration but contains no product
logic.

The durable ownership split remains unchanged:

```text
Provider transcripts                 source evidence
        |
        v
agent_sessions + agent_events         private SQLite evidence
        |
        +-------------------------+
        |                         |
        v                         v
work_memories                 Markdown Vault
typed current state           durable human-readable knowledge
        |                         |
        +------------+------------+
                     v
              MemoryService
                     |
              stdio MCP adapter
                     |
        Codex / Claude / NOOA / other hosts
```

This is not an agent framework and does not execute model-generated code. It is
the persistent memory boundary that agent frameworks call.

## 2. Product problem

AWM currently has a strong record layer and a durable Wiki layer:

- `agent_sessions` and `agent_events` retain normalized evidence;
- the Vault stores retained session projections and distilled Markdown;
- SQLite FTS5 searches both layers.

The missing loop is reuse. A future agent can search AWM manually, but there is
no typed contract for determining the current workspace state, retrieving a
bounded context package, following provenance, or proposing a state update.
Consequently AWM behaves more like an archive plus Wiki than active work memory.

The feature must close this loop without turning AWM into another agent runtime:

```text
capture -> retain -> distill -> recall -> continue work -> propose update
   ^                                                        |
   +--------------------------------------------------------+
```

## 3. Prior art and what is borrowed

The design borrows interface ideas from NVIDIA NOOA and `nooa-memory`:

- memory is available to an agent through explicit typed operations;
- small current state is available before deeper recall;
- detailed information is disclosed progressively;
- recalled items carry stable identities and source references;
- live or authoritative values are referenced instead of copied blindly;
- writes are separate from reads.

References:

- https://github.com/NVIDIA-NeMo/labs-OO-Agents
- https://github.com/NVIDIA-NeMo/labs-OO-Agents/tree/main/packages/nooa-memory

AWM deliberately does **not** copy these NOOA choices:

- AWM does not own an agent loop or install hooks into an agent object.
- AWM does not execute Python generated by a model.
- AWM does not make an LLM call during context, recall, open, or candidate write.
- AWM does not use per-agent ownership. The memory belongs to the person; the
  producing client is provenance, not the owner.
- AWM does not add vector search in this slice. Existing SQLite FTS5 is the
  deterministic first retrieval engine.
- AWM does not automatically confirm model-authored memory.

The MCP implementation uses the official Python SDK v2, the current stable
line as of this design:

- https://github.com/modelcontextprotocol/python-sdk
- dependency: `mcp>=2,<3`
- server type: `from mcp.server import MCPServer`
- transport: stdio only for this slice

The v2 server supports both current and earlier MCP clients. Do not use the v1
`FastMCP` import path and do not hand-roll JSON-RPC.

## 4. Architectural flag

The feature mostly fits the current service/store/composition-root shape, but
three small reshapes are required before the transport is added:

1. Session evidence selection currently lives in
   `workflows/distill/prompt.py`. Move the deterministic selection mechanism to
   a session-owned module so distillation and recall share one bounded policy.
2. Search query parsing currently lives as local functions in
   `services/search/service.py`. Give it a named typed query mode so human search
   can retain strict matching while agent recall uses escaped recall-oriented
   matching.
3. The new state needs a first-class `services/memory/` owner and store. Do not
   add general-purpose JSON state columns to `agent_sessions`, and do not make
   `SessionsService` own active memory.

No broader rewrite is authorized. In particular, do not migrate existing
session rows, rewrite the Vault, replace search, or introduce a generic plugin
registry.

## 5. Product invariants

These rules are mandatory and should be encoded in tests.

1. **Provider neutrality.** `services/memory/` imports no NOOA, MCP, Codex,
   Claude, or model-provider package.
2. **Person ownership.** A memory producer is recorded, but there is no
   provider-owned or agent-owned namespace that prevents the user from reading
   or reviewing their own memory.
3. **Evidence remains canonical.** `agent_events` is the source for retained
   transcript evidence. A work-memory item may summarize or reference evidence;
   it never replaces it.
4. **Markdown remains durable knowledge.** Confirmed working state stays in
   private SQLite. Durable cross-machine knowledge remains ordinary Markdown in
   the Vault and is still produced through the existing distillation workflow.
5. **Deterministic reads.** Context and recall make no AI calls and have fixed
   budgets, ordering, and source rules.
6. **Progressive disclosure.** `context` returns a small package. `recall`
   returns excerpts. `open` is required for a larger source body.
7. **Explicit content permission.** MCP returns no private bodies unless the
   server was launched with an explicit content level and destination.
8. **Candidate-only agent writes.** MCP clients can create candidates only.
   They cannot confirm, reject, resolve, supersede, delete, distill, or edit the
   Vault.
9. **No arbitrary file read.** AWM dereferences only AWM memory, Wiki, and
   retained-session references. File and URL references are returned to the
   caller but never opened by the MCP server.
10. **Bounded output.** Every tool has a hard item count and character limit.
11. **Provenance survives.** Every recall hit and work-memory item has a stable
    `work://` reference and typed sources.
12. **No protocol corruption.** An stdio server writes MCP frames only to
    stdout. Diagnostics use `logging` to stderr.
13. **No silent conflict.** Mutable memory operations use a revision and fail on
    stale updates.
14. **Candidates never influence agents.** Candidate and rejected items are
    excluded from ordinary context and recall.

## 6. Terminology

Use these names consistently in code, CLI, API, UI, tests, and documentation.

| Name | Meaning |
| --- | --- |
| work memory | typed current state kept in private SQLite |
| durable knowledge | canonical Markdown under the configured Vault |
| evidence | retained `AgentSession` and `AgentEvent` records |
| candidate | an untrusted proposed memory awaiting user review |
| confirmed memory | user-approved current state eligible for context/recall |
| scope | `global` or one normalized workspace |
| context | bounded active state plus optional task-relevant recalls |
| recall | lexical retrieval of memory, Wiki, and authorized evidence |
| open | bounded dereference of one canonical `work://` reference |
| producer | client that proposed the item, never its owner |

Do not use `snapshot` for an individual memory row. `WorkContext` is a read
projection assembled from rows. Do not call a candidate `remembered` or
`confirmed` in user-facing text.

## 8. Public call shape

The Python application surface must feel like this:

```python
policy = MemoryAccessPolicy(
    client="nooa",
    content_level=MemoryContentLevel.KNOWLEDGE,
    destination=MemoryDestination.REMOTE,
    allow_write_candidates=True,
)

context = app.memory.context(
    ContextRequest(
        workspace=Path.cwd(),
        task="Continue the active-memory interface design",
        max_chars=12_000,
    ),
    policy,
)

result = app.memory.recall(
    RecallRequest(
        query="why SQLite remains the evidence store",
        workspace=Path.cwd(),
        limit=8,
        max_chars=12_000,
    ),
    policy,
)

document = app.memory.open(
    OpenMemoryReference(
        reference="work://wiki/decisions/sqlite-evidence.md",
        query="evidence store",
        max_chars=16_000,
    ),
    policy,
)

candidate = app.memory.propose(
    ProposeMemory(
        scope=MemoryScope.for_workspace(Path.cwd()),
        kind=MemoryKind.DECISION,
        title="AWM stays provider-neutral",
        content="AWM exposes memory through MCP and does not depend on NOOA.",
        importance=4,
        basis="Decision made while designing the active-memory interface.",
        sources=(
            MemorySource(
                kind=MemorySourceKind.SESSION,
                reference="work://session/ses_...",
            ),
        ),
        producer="nooa",
    ),
    policy,
)
```

Administrative transitions are a separate user surface:

```python
confirmed = app.memory.confirm(
    MemoryTransition(memory_id=candidate.memory_id, expected_revision=1)
)
resolved = app.memory.resolve(
    MemoryTransition(memory_id=confirmed.memory_id, expected_revision=2)
)
```

The MCP adapter never calls the administrative methods.

## 9. Domain models

All shaped data uses `AgentWorkMemoryModel`, enums, and static attributes. Do not
pass loose structured dictionaries through services.

### 9.1 Enumerations

```python
    DECISION = "decision"

class MemoryReviewState(StrEnum):

    CONFIRMED = "confirmed"
    REJECTED = "rejected"


class MemoryLifecycle(StrEnum):
    ACTIVE = "active"
    RESOLVED = "resolved"
    SUPERSEDED = "superseded"


class MemoryScopeKind(StrEnum):
    GLOBAL = "global"
    WORKSPACE = "workspace"


class MemorySourceKind(StrEnum):
    SESSION = "session"
    WIKI = "wiki"
    MEMORY = "memory"
    FILE = "file"
    URL = "url"


class MemoryContentLevel(StrEnum):
    METADATA = "metadata"
    KNOWLEDGE = "knowledge"
    EVIDENCE = "evidence"

    REMOTE = "remote"
```

The taxonomy is intentionally AWM-specific. Sessions already represent
episodes, procedures belong in the Wiki, and reflections are produced by
distillation. Do not import NOOA's complete taxonomy.

### 9.2 Scope

```python
class MemoryScope(AgentWorkMemoryModel):
    kind: MemoryScopeKind
    key: str
    workspace: Path | None = None
```

Rules:

- global scope is exactly `kind=global`, `key=global`, `workspace=None`;
- workspace scope uses `normalized_workspace_path(...)` from the session
  boundary;
- its key is `workspace:` plus the normalized path string case-folded exactly
  as `same_workspace(...)` currently compares paths;
- the original normalized path is stored for display;
- scope construction happens through named functions in `memory/scope.py`, not
  by callers assembling keys;
- a workspace need not currently exist because retained remote or disconnected
  workspaces remain valid memory scopes.

### 9.3 Source references

```python
class MemorySource(AgentWorkMemoryModel):
    kind: MemorySourceKind
    reference: str
    note: str | None = None
```

Canonical references:

```text
work://memory/mem_<id>
work://session/ses_<id>
work://wiki/<percent-encoded-vault-relative-path>
file:<caller-owned-relative-or-absolute-reference>
https://...
```

Validation rules:

- `session`, `wiki`, and `memory` references must use their canonical `work://`
  form;
- every submitted session, Wiki, or memory reference must resolve at write
  time; dangling AWM references are rejected;
- a reference to the current not-yet-collected client session may be omitted;
  `basis` remains required and the Viewer must label the item as having no
  retained source;
- file references are retained as opaque provenance labels and are not required
  to exist; URL references must be absolute `https` URLs;
- file and URL references are never opened by AWM's agent interface;
- maximum sources per memory: 16;
- maximum source note: 500 characters.

### 9.4 Work-memory record

```python
class WorkMemory(AgentWorkMemoryModel):
    memory_id: str
    scope: MemoryScope
    kind: MemoryKind
    title: str
    content: str
    importance: int
    review_state: MemoryReviewState
    lifecycle: MemoryLifecycle
    basis: str
    sources: tuple[MemorySource, ...]
    producer: str
    revision: int
    created_at: datetime
    updated_at: datetime
    reviewed_at: datetime | None = None
    superseded_by: str | None = None
```

Bounds:

- title: 1-160 characters;
- content: 1-4,000 characters;
- basis: 1-1,000 characters;
- producer: normalized identifier matching `^[a-z0-9._-]{1,64}$`;
- importance: integer 1-5;
- new candidates start at revision 1;
- model validators reject illegal review/lifecycle combinations.

State rules:

- candidates are always active;
- rejected items are never active context, regardless of lifecycle;
- confirmed items can be active, resolved, or superseded;
- only confirmed active items appear in normal context and recall;
- confirming a new workspace goal atomically supersedes the previous confirmed
  active goal in that scope;
- resolving is allowed for goal, todo, and question;
- decision, constraint, fact, and preference leave active state only through
  supersession;
- rows are never hard-deleted through public product verbs.

## 10. SQLite schema

Append these idempotent tables to the active schema in
`src/agentworkmemory/database.py`:

```sql
CREATE TABLE IF NOT EXISTS work_memories (
  memory_id       TEXT PRIMARY KEY,
  scope_kind      TEXT NOT NULL,
  scope_key       TEXT NOT NULL,
  workspace_path  TEXT,
  kind            TEXT NOT NULL,
  title           TEXT NOT NULL,
  content         TEXT NOT NULL,
  importance      INTEGER NOT NULL,
  review_state    TEXT NOT NULL,
  lifecycle       TEXT NOT NULL,
  basis           TEXT NOT NULL,
  sources         TEXT NOT NULL,
  producer        TEXT NOT NULL,
  revision        INTEGER NOT NULL,
  created_at      TEXT NOT NULL,
  updated_at      TEXT NOT NULL,
  reviewed_at     TEXT,
  superseded_by   TEXT REFERENCES work_memories(memory_id)
);

CREATE INDEX IF NOT EXISTS idx_work_memories_scope
  ON work_memories(scope_key, review_state, lifecycle, kind);

CREATE INDEX IF NOT EXISTS idx_work_memories_review
  ON work_memories(review_state, updated_at DESC);

CREATE UNIQUE INDEX IF NOT EXISTS idx_work_memories_active_goal
  ON work_memories(scope_key)
  WHERE kind = 'goal'
    AND review_state = 'confirmed'
    AND lifecycle = 'active';

CREATE VIRTUAL TABLE IF NOT EXISTS work_memories_fts USING fts5(
  memory_id UNINDEXED,
  title,
  content,
  basis
);

CREATE TABLE IF NOT EXISTS memory_access_receipts (
  access_id       TEXT PRIMARY KEY,
  occurred_at     TEXT NOT NULL,
  client          TEXT NOT NULL,
  operation       TEXT NOT NULL,
  scope_key       TEXT NOT NULL,
  content_level   TEXT NOT NULL,
  destination     TEXT,
  returned_refs   TEXT NOT NULL,
  returned_chars  INTEGER NOT NULL,
  created_memory_id TEXT
);

CREATE INDEX IF NOT EXISTS idx_memory_access_time
  ON memory_access_receipts(occurred_at DESC);
```

Persistence rules:

- `sources` and `returned_refs` are JSON arrays produced and parsed through
  typed Pydantic models; no caller handles their raw shape;
- `work_memories_fts` is updated in the same transaction as `work_memories`;
- rejected and non-active rows may remain in FTS, but every query joins against
  `work_memories` and filters review/lifecycle state;
- receipts never store query text, returned content, candidate content, or
  transcript bodies;
- receipt operation values are a finite enum: `context`, `recall`, `open`, and
  `propose`;
- the new schema is additive. Existing databases require no data migration;
- `agent_sessions`, `agent_events`, and `search_documents` remain unchanged;
- WAL, busy timeout, and foreign-key behavior continue through `open_database`.

`MemoryStore` owns all SQL for these tables. MCP, CLI, Viewer, and workflows
must not import `sqlite3` or issue SQL.

## 11. Memory service responsibilities

`MemoryService` owns these product verbs:

```python
class MemoryService:
    def context(
        self,
        request: ContextRequest,
        policy: MemoryAccessPolicy,
    ) -> WorkContext: ...

    def recall(
        self,
        request: RecallRequest,
        policy: MemoryAccessPolicy,
    ) -> RecallResult: ...

    def open(
        self,
        request: OpenMemoryReference,
        policy: MemoryAccessPolicy,
    ) -> MemoryDocument: ...

    def propose(
        self,
        request: ProposeMemory,
        policy: MemoryAccessPolicy,
    ) -> WorkMemory: ...

    def list(self, request: ListMemories) -> tuple[WorkMemory, ...]: ...
    def get(self, memory_id: str) -> WorkMemory: ...
    def add_confirmed(self, request: AddUserMemory) -> WorkMemory: ...
    def confirm(self, request: MemoryTransition) -> WorkMemory: ...
    def reject(self, request: MemoryTransition) -> WorkMemory: ...
    def resolve(self, request: MemoryTransition) -> WorkMemory: ...
```

Dependencies are injected in `create_app`:

```python
memory = MemoryService(
    MemoryStore(resolved.database_path),
    sessions,
    vault,
    wiki,
    search,
)
```

Expose it as `AgentWorkMemory.memory`. Do not place memory methods directly on
the application object.

### 11.1 Reads

- `context` assembles confirmed active state for exact workspace scope and
  global preferences, then optionally recalls against `request.task`.
- `recall` searches confirmed active work memory and existing AWM search
  documents, classifies hits, enforces scope ordering, content access, and the
  output budget.
- `open` parses one canonical `work://` reference and returns a bounded document.
- all reads append a metadata-only access receipt after successful assembly;
- a receipt failure must not fail the requested read, but it must be logged to
  stderr by adapters or the calling edge.

### 11.2 Writes

- `propose` is append-only and requires `policy.allow_write_candidates`;
- `add_confirmed` is for a direct user CLI action and is not exposed through
  MCP;
- `confirm`, `reject`, and `resolve` compare `expected_revision` in the SQL
  `WHERE` clause and raise `MemoryConflictError` when no row matches;
- transitions and active-goal supersession happen in one immediate transaction;
- confirming a new goal first marks the prior active goal `superseded`, sets its
  `superseded_by` to the new goal ID, increments the prior goal's revision, and
  then confirms the new goal before commit;
- a successful transition increments revision exactly once;
- retries with the already-achieved state and current revision are idempotent;
- no memory operation edits a Markdown file or runs a curator.

## 12. Search and retrieval policy

### 12.1 Search query reshape

Move query parsing to `services/search/query.py`:

```python
class SearchQueryMode(StrEnum):
    ALL_TERMS = "all-terms"
    ANY_TERM = "any-term"


class SearchQuery(AgentWorkMemoryModel):
    original: str
    terms: tuple[str, ...]
    mode: SearchQueryMode
```

Rules:

- maximum input query: 500 characters;
- split only on whitespace for this slice;
- drop empty and punctuation-only terms;
- escape double quotes and all FTS syntax;
- human `awm search` remains `ALL_TERMS` to preserve its existing contract;
- memory recall uses `ANY_TERM` to avoid zero results from natural question
  scaffolding;
- do not add stop-word dictionaries, stemming, query rewriting, or an LLM call.

Add a typed `SearchService.find_for_recall(...)` method rather than adding flags
to CLI or Viewer calls. It returns ordered search results with enough identity
to resolve a Wiki or session source. Existing `find(...)` behavior remains.

### 12.2 Work-memory lexical candidates

`MemoryStore.recall_candidates(...)` queries `work_memories_fts`, joins the
canonical table, and filters:

```text
review_state = confirmed
lifecycle = active
scope_key in {exact workspace, global}
```

FTS ordering is retained within each scope group. Empty queries never query FTS;
`context` uses deterministic state ordering instead.

### 12.3 Final deterministic ordering

Recall candidates are grouped in this exact order:

1. matching confirmed active work memories in the exact workspace;
2. matching Wiki pages whose source sessions include the exact workspace;
3. matching global confirmed active work memories;
4. other matching Wiki pages;
5. matching retained sessions in the exact workspace, only at `evidence` level.

Within a group:

- work memories order by `importance DESC`, FTS rank, `updated_at DESC`, and
  `memory_id`;
- Wiki and session results retain SQLite FTS order, then identity as a stable
  tie-break;
- duplicate canonical references collapse to the first hit;
- session results outside the exact workspace are excluded, not merely ranked
  lower;
- candidates, rejected memories, resolved memories, session inbox Markdown,
  generated index pages, `Home.md`, and `README.md` are excluded.

This slice intentionally avoids cross-source numeric score normalization.
Deterministic source groups are easier to audit than pretending unrelated BM25
scores are comparable.

### 12.4 Wiki workspace association

A Wiki page is associated with a workspace when any of its
`source_session_ids` resolves to an `AgentSession` whose `cwd` matches the
requested scope via `same_workspace(...)`. Pages without a matching source are
global Wiki candidates.

Do not infer workspace from page text, filenames, tags, or project names.

## 13. Context assembly and budgets

Constants live in `services/memory/retrieval.py`:

```text
MAX_QUERY_CHARS             500
DEFAULT_RECALL_LIMIT          8
MAX_RECALL_LIMIT             20
DEFAULT_CONTEXT_CHARS    12,000
DEFAULT_RECALL_CHARS     12,000
DEFAULT_OPEN_CHARS       16,000
MAX_OUTPUT_CHARS         32,000
MAX_HIT_EXCERPT_CHARS     2,000
```

All budgets count Python characters, matching current distillation behavior.
They are not presented as exact token counts.

`context` fills its budget in this order:

1. exact-scope active goal, at most one;
2. exact-scope constraints;
3. exact-scope decisions;
4. exact-scope pending todos;
5. exact-scope open questions;
6. exact-scope facts;
7. global preferences;
8. task-driven recall hits if `task` is non-empty.

Within each collection use `importance DESC`, `updated_at DESC`, `memory_id`.
One item cannot consume more than 4,000 content characters. The final item may
be truncated and must be marked by the top-level `truncated` flag. Do not cut a
Unicode code point and do not silently omit the source reference.

The context call never includes session evidence automatically, even when the
server's content level is `evidence`. The agent must call `recall` or `open` for
evidence. This prevents large or sensitive transcript bodies from appearing in
every turn.

## 14. Shared session evidence selection

Move the following from `workflows/distill/prompt.py` into
`services/sessions/evidence.py`:

- `EvidenceExcerpt`;
- `select_evidence`;
- `excerpt`;
- the constants governing first-intent and recent-event selection.

The distillation prompt imports the service-owned policy without behavioral
change.

Add a query-aware selector for agent recall:

```python
select_matching_evidence(
    events: tuple[AgentEvent, ...],
    query: SearchQuery,
    max_chars: int,
) -> tuple[EvidenceExcerpt, ...]
```

Exact behavior:

1. score each event by the number of distinct query terms present under
   case-folded substring matching;
2. discard zero-match events;
3. order by score descending, then event sequence descending;
4. retain at most eight events;
5. restore sequence order in the returned projection;
6. fill the character budget with the same bounded excerpt helper;
7. if nothing matches, fall back to existing first-intent plus recent-outcome
   selection.

This is deterministic evidence selection, not semantic interpretation.

## 15. Content access policy

```python
class MemoryAccessPolicy(AgentWorkMemoryModel):
    client: str
    content_level: MemoryContentLevel
    destination: MemoryDestination | None = None
    allow_write_candidates: bool = False
```

### Metadata

- returns IDs, kinds, titles, status, timestamps, counts, and source references;
- returns no work-memory content, basis, Wiki body, event body, or excerpts;
- destination is optional.

### Knowledge

- includes confirmed work-memory content and durable Wiki excerpts/bodies;
- excludes `agent_events` bodies and retained session Markdown bodies;
- requires an explicit `local` or `remote` destination at server startup.

### Evidence

- includes everything permitted by `knowledge`;
- additionally permits bounded `agent_events` excerpts and session `open`;
- requires an explicit `local` or `remote` destination at server startup.

The destination is an auditable user declaration. AWM cannot independently
determine whether an MCP host sends tool output to a local or hosted model.

Content access is monotonic:

```text
metadata < knowledge < evidence
```

No tool argument can raise the policy established at server startup.

## 16. MCP adapter

### 16.1 CLI startup contract

Add:

```text
awm mcp serve
  --client NAME
  --content metadata|knowledge|evidence
  [--destination local|remote]
  [--allow-write-candidates]
```

Defaults and validation:

- `--client` is required and validated as the producer identifier;
- `--content` defaults to `metadata`;
- `--destination` is forbidden for metadata and required otherwise;
- candidate writes are disabled unless explicitly enabled;
- transport is stdio and is not user-configurable in this slice;
- `--state-dir` remains the existing global CLI override;
- startup fails before serving if configuration or the database cannot open;
- no interactive prompt is allowed because MCP hosts launch the server
  unattended.

Examples:

```powershell
# Safe discovery only
awm mcp serve --client nooa --content metadata

# Hosted model may receive durable knowledge but not transcripts
awm mcp serve --client nooa --content knowledge --destination remote

# Local model may receive retained evidence and propose candidates
awm mcp serve --client local-nooa --content evidence --destination local `
  --allow-write-candidates
```

### 16.2 MCP tools

Expose exactly these tools in v1:

```text
awm_context
awm_recall
awm_open
awm_remember_candidate
```

#### `awm_context`

Inputs:

```python
workspace: str | None = None
task: str | None = None
max_chars: int = 12_000
```

Returns `WorkContext`. If workspace is absent, use the MCP server process's
startup working directory captured once before serving.

#### `awm_recall`

Inputs:

```python
query: str
workspace: str | None = None
limit: int = 8
max_chars: int = 12_000
```

Returns `RecallResult`. It does not accept a content-level argument.

#### `awm_open`

Inputs:

```python
reference: str
query: str | None = None
max_chars: int = 16_000
```

Returns a typed `MemoryDocument` with `reference`, `title`, `content`,
`content_level`, `returned_chars`, and `truncated`. Metadata policy returns
`content=None`. Wiki references require knowledge; session references require
evidence. Memory references follow metadata/knowledge rules.

#### `awm_remember_candidate`

Inputs:

```python
kind: MemoryKind
content: str
workspace: str | None
title: str
importance: int = 3
basis: str
sources: tuple[MemorySource, ...] = ()
```

Returns `MemoryCandidateReceipt`. The tool description must say explicitly:
"This creates an unconfirmed candidate. It does not change current context or
the Wiki until the user confirms it."

If writes are disabled, return a normal MCP tool error with a concise actionable
message. Do not expose a stack trace or absolute state path.

### 16.3 Server construction

The integration shape is:

```python
def create_memory_mcp_server(
    memory: MemoryService,
    policy: MemoryAccessPolicy,
    *,
    startup_workspace: Path,
) -> MCPServer:
    server = MCPServer("Agent Work Memory")

    @server.tool()
    def awm_context(...) -> dict[str, object]:
        result = memory.context(..., policy)
        return result.model_dump(mode="json")

    # Other tools follow the same adapter-only mapping.
    return server
```

`run_memory_mcp_server(...)` calls `server.run(transport="stdio")`. Confirm the
exact v2 call against the locked SDK during implementation; do not use a v1
compatibility import.

The adapter catches expected domain errors and turns them into readable tool
errors. Unexpected exceptions are logged with redacted messages and surfaced as
`Internal memory error`.

## 17. Administrative CLI

Add one command family:

```text
awm memory list
  [--workspace PATH]
  [--global]
  [--kind KIND]
  [--review candidate|confirmed|rejected]
  [--lifecycle active|resolved|superseded]

awm memory show MEMORY_ID

awm memory add
  --kind KIND
  --title TITLE
  --content CONTENT
  [--workspace PATH | --global]
  [--importance 1..5]
  --basis TEXT
  [--source REFERENCE ...]

awm memory confirm MEMORY_ID --revision N
awm memory reject MEMORY_ID --revision N
awm memory resolve MEMORY_ID --revision N
```

Rules:

- `add` is a direct user action and creates confirmed memory;
- absent scope defaults to the command's current working directory, never
  global;
- `--global` and `--workspace` are mutually exclusive;
- list defaults to active confirmed memory for the current workspace;
- candidate review commands print the new state and revision;
- stale revision exits nonzero with the current revision in the message;
- `--json` is not introduced in this slice because the active AWM CLI has no
  global JSON contract. MCP is the machine interface.

Keep rendering in small named CLI functions. The CLI calls service verbs and
contains no lifecycle policy.

## 18. Viewer review surface

Do not add a fifth primary navigation tab. The current product contract keeps
Today, Sessions, Knowledge, and Activity as primary surfaces.

Add a **Memory candidates** band to Today:

```text
Memory candidates (3)

[Decision] AWM stays provider-neutral

Proposed by: nooa
Basis: Decision made while designing...

[Review] [Reject]
```

Selecting Review opens the existing detail-peek pattern with:

- full candidate title and content;
- kind, importance, workspace, producer, timestamps, and revision;
- basis;
- clickable session/Wiki/memory sources;
- Confirm and Reject actions;
- a clear notice that candidates are not supplied to agents.

Add service projections, then thin API routes:

```text
GET  /api/memory/candidates
GET  /api/memory/{memory_id}
POST /api/memory/{memory_id}/confirm
POST /api/memory/{memory_id}/reject
POST /api/memory/{memory_id}/resolve
```

Mutation bodies carry `expected_revision`. Existing
`X-AWM-Action: viewer` protection is mandatory. Map missing rows to 404, stale
revisions and illegal transitions to 409, and invalid input to 422.

The Viewer never performs ranking or accesses `MemoryStore` directly.

## 19. Opening references

`MemoryService.open(...)` dispatches by parsed reference kind:

### Memory

- load the row by ID;
- candidates and rejected rows are available only through administrative
  service/Viewer calls, not agent `open`;
- apply metadata or knowledge redaction;
- return sources but do not recursively open them.

### Wiki

- percent-decode one Vault-relative `.md` path;
- reject absolute paths, `..`, symlinks, non-Markdown files, generated indexes,
  `Home.md`, `README.md`, translations, and `inbox/agent-sessions`;
- require knowledge access;
- read canonical Markdown through a Vault-owned safe read method;
- return a query-centered excerpt when query is supplied; otherwise return the
  leading bounded body.

### Session

- require evidence access;
- load events from `SessionsService`;
- use `select_matching_evidence` when query is supplied;
- otherwise use first-intent plus recent-outcome selection;
- format event sequence, kind, role, label, timestamp, and bounded content;
- never read the original provider JSONL directly.

Unknown schemes and unsupported kinds fail closed.

## 20. Error contract

Add domain errors under `services/memory/errors.py`:

```python
MemoryNotFoundError
MemoryConflictError
MemoryTransitionError
MemoryAccessDeniedError
MemoryReferenceError
MemoryBudgetError
```

Messages shown to an agent must be concise and actionable:

```text
Memory candidate writes are disabled for this AWM connection.
Session evidence requires an MCP server started with --content evidence.
Memory mem_... changed; retry with revision 3.
Unknown AWM reference: work://memory/mem_...
```

Do not include SQL, stack traces, access tokens, transcript text, environment
variables, or full private state paths in surfaced errors.

## 21. Concurrency and idempotency

AWM may sync sessions, serve the Viewer, and answer multiple agent processes
against one WAL database.

- candidate insertion uses a generated `mem_` ID and one transaction;
- FTS insertion and candidate insertion commit together;
- review transitions use `BEGIN IMMEDIATE`;
- SQL updates include `memory_id` and `revision` in the predicate;
- confirming a goal selects and supersedes any existing active goal in the same
  transaction;
- FTS rows are updated for content changes and remain for historical rows;
- list and recall queries use deterministic tie-breaks;
- access-receipt IDs use UUIDs because retries are independent observations;
- no in-memory singleton holds current state between MCP calls.

Do not add a daemon cache. SQLite and the Vault remain the authoritative read
sources.

## 24. Test plan

### Core model and store

- fresh and existing databases create the additive schema;
- every enum and field bound rejects invalid data;
- source JSON round-trips through typed models;
- candidate insertion and FTS insertion are atomic;
- candidates never appear in ordinary context or recall;
- confirm/reject/resolve transitions enforce legal source states;
- stale revisions fail without partial writes;
- confirming a second goal supersedes exactly one previous active goal;
- global and workspace scopes remain distinct;
- disconnected workspace paths remain addressable;
- rows survive application reconstruction.

### Retrieval

- current context follows the exact kind ordering;
- global preferences appear after exact-scope state;
- other workspaces never leak into context;
- natural-question ANY-term recall returns relevant lexical matches;
- existing human search remains ALL-terms;
- matching workspace Wiki pages outrank global Wiki pages;
- session evidence appears only with evidence access and exact workspace;
- metadata returns no private body fields;
- knowledge returns memory/Wiki bodies but not sessions;

- unsupported references and path traversal fail closed;
- candidate/rejected/resolved items cannot be opened through the agent surface;

### MCP

## 25. End-to-end acceptance scenarios

### Scenario 1: resume a workspace

1. The user adds a confirmed goal, decision, and todo for workspace A.
2. Workspace B has unrelated memory.
3. A NOOA agent calls `awm_context` from workspace A.
4. The response contains A's goal, decision, and todo, plus applicable global
   preferences.
5. It contains no workspace B content and no candidate content.

### Scenario 2: recover a prior decision

1. A retained session and durable decision page support the SQLite storage
   decision.
2. The agent calls `awm_recall("why SQLite remains the evidence store")` under
   knowledge access.
3. The durable decision page is returned with a stable `work://wiki/...`
   reference.
4. No session event body is returned.
5. `awm_open` returns a bounded canonical Wiki excerpt and source session IDs.

### Scenario 3: inspect evidence explicitly

1. The server is restarted with evidence access and an explicit destination.
2. The agent recalls the same decision and then opens its session reference.
3. AWM returns selected normalized events, not the raw provider JSONL.
4. Output stays under the requested budget and records an access receipt without
   storing the query or returned body.

### Scenario 4: propose and review memory

1. The MCP server is started with candidate writes enabled.
2. The agent calls `awm_remember_candidate` with a decision and source.
3. The tool returns `candidate`, revision 1.
4. A subsequent `awm_context` does not return it.
5. The user confirms it in the Viewer or CLI.
6. The row becomes confirmed revision 2 and appears in context.
7. The confirmation does not edit the Vault or invoke a curator.

### Scenario 5: preserve provider neutrality

1. The same MCP configuration is used by a NOOA agent and another MCP host.
2. Both receive the same structured context and references.
3. AWM core has no import or branch for either host.

## 26. Success criteria

The feature is complete only when all are true:

- an active agent can retrieve workspace state without replaying a transcript;
- every returned non-metadata statement has a stable AWM reference;
- transcript bodies never leave AWM without evidence-level startup permission;
- agent writes remain candidates until a user action confirms them;
- current context stays within a caller-controlled hard budget;
- existing capture, sync, distillation, search, Viewer, and Vault Git behavior
  remains compatible;
- NOOA consumes AWM through MCP with no AWM dependency on NOOA;
- the installed package passes the stdio smoke test;
- focused and complete AWM gates pass;
- implementation review finds no unresolved high- or medium-severity issues.

## 27. Explicit non-goals

- replacing NOOA's internal memory package;
- training, fine-tuning, or hosting an LLM;
- model-generated Python execution;
- automatic memory confirmation;
- automatic pre-turn injection into every provider session;
- editing provider configuration without an explicit user action;
- Streamable HTTP, SSE, remote MCP hosting, authentication, or multi-user
  service operation;
- embeddings, vector databases, rerankers, knowledge-graph spreading, ACT-R
  activation, decay, or automatic forgetting;
- recursively dereferencing arbitrary files or URLs;
- syncing SQLite work memory through the Vault Git repository;
- moving runtime state into Markdown;
- replacing existing session capture or distillation;
- a generic adapter registry for one MCP implementation.

## 28. Rejected alternatives

### Make AWM depend directly on NOOA

Rejected because AWM must serve existing Codex, Claude, Cursor, and future
agents. A direct dependency would reverse the product boundary and inherit a
research framework's lifecycle.

### Serialize a complete NOOA Agent object

Rejected because LLM clients, database connections, locks, tasks, and runtime
methods are not durable state. AWM persists typed meaning and evidence, then a
runtime reconstructs its own agent.

### Put active state in `agent_sessions`

Rejected because provider session records are evidence, while goals and todos
can span sessions and providers. The reasons to change differ.

### Write agent proposals directly to the Vault

Rejected because unreviewed model output would become durable knowledge and
Git-visible source. Candidate review must precede confirmation, and existing
distillation remains the only AI-assisted Wiki mutation path.

### Return all matching transcript text from context

Rejected for privacy, cost, and relevance. Context is state-first; evidence is
explicit progressive disclosure.

### Add vectors immediately

Rejected because AWM already has FTS5, the first value to prove is the feedback
loop, and no measured retrieval set currently justifies embedding machinery.
The service/store boundary leaves a future hybrid candidate generator additive.

### Expose the existing Viewer HTTP API to agents

Rejected because it is a browser adapter with different security assumptions,
no agent-specific content policy, and no stable machine contract. stdio MCP has
no listening socket and is supported by the intended agent hosts.
